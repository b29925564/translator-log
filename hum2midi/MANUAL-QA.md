# 人工驗收（規劃書 13.4）

這些項目需要真的 Mac、真的麥克風與 GarageBand，自動化測試做不到。每完成一項就打勾，有問題的地方記在最後的「結果」，必要時更新 `DECISIONS.md`。

開發伺服器：

```sh
cd hum2midi
npm install
npm run dev     # 開 http://localhost:5173
```

> 麥克風只能在 `localhost` 或 `https` 下用，不要直接雙擊 `index.html`。

---

## 1. 〈小星星〉第一句

- [ ] Chrome：用 Mac 內建麥克風，按空白鍵，哼「C C G G A A G」（一閃一閃亮晶晶），再按空白鍵。
  - 期望：至少 6/7 個音正確（60 60 67 67 69 69 67，或整體移調後相對音高正確）。
  - 若漏音：把右側「靈敏度」往右調；若一個音被切成兩個：把「切分敏感度」往左調。
- [ ] Safari：同上。

## 5. 說話變唱歌（隱藏模式）

- [ ] 在錄音頁連點 logo 三下（或按 `⇧S`）→ 頂部出現第 4 個頁籤；重新整理後仍在。
- [ ] 錄「今天晚上不想加班」之類的一句話（1–3 秒）→ 自動修剪頭尾靜音。
- [ ] 循環 10 次、停頓 0.8 秒：每一次聽起來完全相同（沒有變調、沒有效果）；可以用 1–5 鍵或按鈕評分；結束後有評分曲線。
- [ ] 揭曉：抽出的旋律疊在原始音高曲線上；誇張化滑桿有效。
- [ ] 配和弦：原聲＋和弦、旋律＋和弦、長音／分解和弦、鼓組、循環播放。
- [ ] 匯出 3 軌 MIDI，拖進 GarageBand（見 4-E）。
- [ ] 從 Takes 庫框選一段長錄音當作那句話。

## 6. Safari 特別注意

自動化測試只在 Chromium 上跑。下列是已知 Safari 差異與目前的處理方式，請逐項確認：

- [ ] `AudioContext.outputLatency`：Safari 可能沒有 → 改用 `baseLatency`（`src/audio/context.ts`），節拍器對齊靠手動偏移。
- [ ] AudioWorklet 錄音（Safari 14.1+）：錄完的長度與實際時間相符、沒有斷音。
- [ ] 麥克風權限：Safari 每次載入頁面可能都會再問；`navigator.permissions.query('microphone')` 可能不支援（已 try/catch，改成第一次按錄音才開麥克風）。
- [ ] 第一次按空白鍵才建立／恢復 AudioContext（自動播放政策）。
- [ ] IndexedDB 存 Blob（私密瀏覽模式下可能失敗 → 應該看到「沒辦法存進 Takes 庫」的提示，但仍可編輯與匯出）。
- [ ] `<dialog>`、`:focus-visible`、`accent-color`（Safari 15.4+）。
- [ ] 下載檔名正確（`a.download` ＋ blob URL）。
- [ ] `⌘1–⌘9` 在 Safari 可能被拿去切換分頁 → 用不加修飾鍵的 `1–4`。
